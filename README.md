# Factory Fault Tracker — starter MVP

A small, self-hostable PWA starter for factory fault reports.

## Features in this starter
- Mobile-friendly report form
- Camera photo attachment
- Barcode/QR scan through browser camera (requires HTTPS and camera permission)
- Unique fault ID generated by the backend
- SQLite persistence and photo storage in a Docker volume
- Fault list, assignment field, status updates and resolution notes
- Optional Microsoft Teams Workflow webhook notification on new report
- Basic PWA manifest and service worker

## Run locally with Docker
1. Install Docker Desktop (Windows/macOS) or Docker Engine + Compose (Linux).
2. Copy `.env.example` to `.env`.
3. Optional: set `TEAMS_WEBHOOK_URL` in `.env` to your Teams Workflow HTTP webhook URL.
4. From this folder run:
   ```bash
   docker compose up --build -d
   ```
5. Open `http://localhost:8000`.

For other phones on the same LAN, use `http://SERVER-LAN-IP:8000` for an initial test. Camera access and PWA installation generally require HTTPS outside localhost. Do not use this HTTP setup for production.

## Important production gaps
This is a prototype, not yet safe for production use in a factory. Before real deployment:
- Put it behind HTTPS (e.g. company reverse proxy / approved internal ingress).
- Add Microsoft Entra ID sign-in or another approved identity provider.
- Enforce role-based permissions and audit history for all status/assignment changes.
- Add upload size limits, image validation, malware scanning policy, backups and retention rules.
- Restrict network access and protect secrets.
- Use PostgreSQL for multi-user production instead of SQLite.
- Review safety process and emergency reporting procedures with the plant's EHS/maintenance owners.

## Teams integration scope
The optional webhook only sends a notification to a channel. It does NOT implement interactive assignment/status buttons inside Teams. For that, implement a Teams bot/Teams app or a Microsoft Graph integration with the tenant administrator's approval and the required permissions. Avoid putting webhook URLs or Graph secrets in browser code.

## API
- `GET /api/health`
- `GET /api/faults`
- `POST /api/faults` (multipart form: reporter, department, asset_code, fault_type, severity, description, optional photo)
- `PATCH /api/faults/{fault_id}` (JSON: status, assignee, resolution)

Allowed statuses: `New`, `Assigned`, `In Progress`, `Resolved`.
